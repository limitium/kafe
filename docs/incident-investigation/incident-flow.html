Architecture

Claude is the producer

It turns project data (code, docs, schema, infra, deployments) and the symptoms into instructions. All the reasoning happens here, away from client data.

Instructions are almost code only

A script, how to run it, how to collect the output and the exact result format. Nothing is left for the other side to interpret.

Qwen is a rich runtime

It executes the instructions inside production with more reach than a fixed set of MCPs: it copes with a missing path or a failed command and shapes the output. It never chooses what to investigate.

Clean borders that can be tightened

One border for what may run, one for what may leave. Either can be made stricter without a redesign: fewer permissions, an allowlist of commands, APS approval for selected requests, aggregates only.

Directions that make it safe

    

      
Client data stays in production
Claude works from code, schema and layout only. Results are checked and reduced to summaries, counts and timings before they leave.

      
Read-only, behind clean borders
A limited service account sets what is possible at all. Checks on the way in and on the way out sit on top, and each border can be tightened if needed.

      
A runtime, not a decision maker
Qwen runs instructions that are almost pure code and returns the result in the requested format. The thinking stays with Claude and the dev team.

      
Everything is recorded
Each request, what ran and what came back is logged and visible to APS.

      
Thin tools
A shell plus a few MCPs the size of a shell script, instead of a large MCP estate to build and maintain.
